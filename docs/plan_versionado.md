\# Plan de versionado — BasketData



\## 1. Herramientas



Se utilizará Git para el control de versiones local y GitHub para el almacenamiento y seguimiento del código fuente.



\## 2. Rama principal



La rama main contendrá las versiones estables y verificadas de la aplicación.



\## 3. Esquema de versionado



Se propone utilizar el versionado semántico:



\- MAJOR: cambios importantes en la aplicación.

\- MINOR: incorporación de nuevas funcionalidades.

\- PATCH: corrección de errores.



\## 4. Versiones previstas



| Versión | Descripción |

|---|---|

| 0.1.0 | Estructura inicial del proyecto. |

| 0.2.0 | Limpieza y procesamiento de datos. |

| 0.3.0 | Implementación de la exploración estadística. |

| 0.4.0 | Implementación del juego interactivo. |

| 0.5.0 | Integración del historial del usuario. |

| 0.9.0 | Reorganización y pruebas del proyecto. |

| 1.0.0 | Entrega final y publicación. |



\## 5. Procedimiento de actualización



1\. Sincronizar el repositorio local.

2\. Realizar las modificaciones.

3\. Ejecutar las pruebas automatizadas.

4\. Registrar los cambios mediante git add.

5\. Crear un commit descriptivo.

6\. Publicar los cambios mediante git push.



\## 6. Archivos excluidos



Los entornos virtuales, archivos temporales, cachés y credenciales privadas serán excluidos mediante .gitignore.
